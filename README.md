## 项目亮点

### 🎯 解决行业痛点

中国文旅产业约 **30%** 的项目因选址不当或合规冲突导致亏损或被叫停。根本原因：

- ❌ 选址决策依赖个人经验，缺乏系统方法论
- ❌ 生态红线、基本农田等合规风险前期识别不足
- ❌ 投资回报预估偏离实际，缺乏量化评估工具

### ✅ 我们的解决方案

**踏歌行智策通**将文旅选址的专家经验沉淀为一套**可执行、可验证、可复用**的智能体系统：

1. **四维决策引擎**（合规35% + 空间25% + 经济20% + 市场20%）
2. **SOP十步选址流程**（从身份认证到三向成果的标准化任务协议）
3. **三层数据溯源体系**（官方🟦 + AI🟩 + 人工🟧，物理阻断AI幻觉）
4. **人机双层确权机制**（AI生成《数据确认函》→ 人工校准确认 → 输出最终建议）

### 🏆 核心优势

| 优势 | 说明 |
|------|------|
| **领域经验结构化** | 将十年一线规划经验固化为18条可配置评分规则 |
| **数据可信度可视化** | 每个数据项标注来源类型，用户可追溯、可修正 |
| **决策过程透明化** | 独创"人机双层确权机制"，从技术上物理阻断AI幻觉 |
| **分钟级响应** | 将复杂的地块禀赋、市场风向、行业政策智能耦合，分钟级输出决策建议 |

## 核心功能

### 1. SOP十步选址流程

从身份认证到三向成果的标准化任务协议：

```
W1 身份认证 → W2 地块框选 → W3 资源调查 → W4 政策引导
→ W5 市场调研 → W6 法规红线 → W7 SWOT分析 → W8 需求澄清
→ W9 战略定位 → W10 三向成果
```

每步含：输入 → 处理 → 输出 → **验证点**（"我已核对"确认机制）

### 2. 四维决策引擎

将文旅选址抽象为 **4 维度 × 18 条规则** 的量化评分体系：

| 维度 | 权重 | 核心规则 | 来源 |
|------|------|---------|------|
| **合规** | 35% | 生态红线-30分硬过滤、耕地保护-20分硬过滤 | 《生态保护红线划定指南》+ 《土地管理法》 |
| **空间** | 25% | 林地+10分、复合景观+10分、规模效应+5分 | 景观生态学 + LID实践 |
| **经济** | 20% | 回报周期惩罚-10分、近郊区位+15分 | 城市旅游圈层理论 |
| **市场** | 20% | 研学需求+10分、市场份额+5分 | 教育部政策 + OTA数据趋势 |

### 3. 数据溯源与人工修正

每个数据项统一结构：`{value, sourceType, sourceName, manualNote}`

| 来源类型 | 颜色 | 可信度 | 说明 |
|---------|------|--------|------|
| `official_api` | 🟦 官方 | 最高 | 来自官方API接口 |
| `ai_aggregation` | 🟩 AI聚合 | 中 | AI从多源聚合生成 |
| `manual` | 🟧 人工 | 需复核 | 用户手动修正或备注 |

**功能**：
- 每个可编辑字段均有 **"修改"** 和 **"补充"** 按钮
- "修改"：覆盖原文
- "补充"：在原文末尾追加（\n分隔）
- 修正后数据项显示橙色备注条，可追溯修改历史

### 4. 人机双层确权机制

独创"人机双层确权机制"，从技术上物理阻断AI幻觉：

1. AI完成海量数据抓取与匹配
2. 自动生成《数据确认函》
3. 必须经由人工校准与确认
4. 系统方可输出最终建议

> 这不仅从技术上物理阻断了AI幻觉的出现几率，更确保了每一个决策都建立在"客观事实+主观确认"的双重基石之上。

## 应用场景

### 场景1：文旅项目选址决策

**用户**：文旅开发商、规划师  
**痛点**：缺乏系统方法论，依赖个人经验  
**解决方案**：
1. 输入目标地块基本信息
2. 系统自动抓取资源、政策、市场数据
3. 输出战略定位建议 + 合规风险预警

### 场景2：文旅项目合规审查

**用户**：政府审批部门、投资方  
**痛点**：合规风险识别不足，后期被叫停  
**解决方案**：
1. 上传项目规划范围
2. 系统自动比对生态红线、基本农田等
3. 输出合规风险报告

### 场景3：文旅市场调研

**用户**：市场研究人员  
**痛点**：数据分散，调研成本高  
**解决方案**：
1. 输入目标区域
2. 系统自动聚合竞品、客群、政策数据
3. 输出市场调研报告

## AVJ 提交材料

本项目按照 **Agent Value Judge (AVJ)** 智能体价值审计框架整理提交材料：

```
avj-submission/
├── project_card.yaml          # 项目信息卡

├── execution_protocols.yaml   # SOP十步任务协议
├── evidence_map.yaml          # Claim-Evidence-Verification 映射
├── open_source_provenance.yaml # 开源来源与团队增量声明
├── feedback_loop.yaml         # 反馈循环与经验沉淀机制
├── adaptation.yaml            # 个体化/情境化适配
├── expert_collaboration.yaml  # 专家协作流程设计

├── safety_boundary.yaml       # 安全边界与责任声明
└── risk_flags.yaml            # 风险标记清单（10项）
```
